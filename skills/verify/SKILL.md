# verify — 실제로 돌려서 확인

빌드·단위 테스트 통과는 "코드가 컴파일된다"는 증거일 뿐 "기능이 된다"는 증거가 아니다. 바뀐 것에 맞는 방법으로 실제 동작을 확인한다.

## 프로젝트 전용 검증 스킬
위치: `.agents/skills/verify-app/SKILL.md` (Codex 가 읽는 위치). Claude Code 용으로 `.claude/skills/verify-app` 를 같은 곳을 가리키는 심볼릭 링크로 둔다.

### 없으면 만든다
코드와 `AGENTS.md` 명령어를 읽고, 실제로 실행해 보면서 아래 다섯 절을 채운다. 추측으로 쓴 명령은 넣지 않는다 — 돌려서 된 것만.
1. **실행**: 앱·서버·CLI 를 띄우는 명령, 필요한 환경변수(값이 아니라 이름), 준비 데이터
2. **준비 확인**: 떴는지 판정하는 방법 (헬스 엔드포인트, 포트, 로그 문구) 과 대기 한도
3. **동작 확인**: 핵심 시나리오(PRD)별로 실제 입력을 넣고 결과를 확인하는 방법 — API 면 curl, 웹이면 브라우저 자동화(Playwright 등), CLI 면 명령과 기대 출력
4. **증거**: 무엇을 남기나 (응답 본문 요약, 스크린샷 경로, 로그 발췌)
5. **정리**: 띄운 프로세스·임시 데이터 정리

### 있으면 실행한다
1. 이번 변경과 관련된 시나리오를 고른다 (`docs/specs/` 의 진행 중 명세 수용 기준 기준). 관련 시나리오가 없으면 시나리오를 추가하자고 제안한다.
2. 절차대로 실행하고 증거를 모은다.
3. 진행 중인 명세가 있으면 `log.md` 에 「verify」 절로 증거를 적는다.
4. 절차가 실제와 달라 실패하면(명령 변경 등) 검증 스킬 자체를 고치고 그 사실을 보고한다. 기능이 실패하면 고치지 말고 실패를 보고한다 — 고치는 것은 `/jig:build` 의 일이다.

보고는 "확인한 것 / 확인하지 못한 것과 이유 / 증거 위치" 세 줄로.
